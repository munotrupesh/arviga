# ARVIGA website

A static, dependency-free catalogue website for furniture and engineering services. Built with HTML, CSS and vanilla JavaScript, generated by a small Node.js build script. No application server or database is required to serve the website.

## Contents

- 74 product pages from the supplied spreadsheet, grouped into six categories.
- Nine engineering/manufacturing service pages based on the services document.
- Home, furniture index, category pages, services index, about, contact, privacy and 404 pages: 96 HTML pages total.
- Four AI-generated concept views per product, image enlargement, example INR prices, finish preferences, quantity and enquiry handoff.
- Product search, category filtering, responsive navigation, scroll reveal and reduced-motion support.

## Build and preview

Requires Node.js 20 or newer. No npm installation is needed.

```sh
npm run build
node check.mjs --complete
npm run preview
```

The local preview uses http://127.0.0.1:4173. The `dist` folder is the deployable website. Authored CSS and JavaScript are tracked directly in `dist/assets`; do not delete the assets folder before rebuilding.

## Edit content

- `data/catalogue.json`: categories and product names from the approved spreadsheet. Duplicate names in different categories have distinct URLs.
- `data/product-details.json`: illustrative INR price, product-specific description and specification discussion points. Prices are examples, not confirmed commercial offers.
- `data/business.json`: verified contact channels, business location, public domain and public indexing flag.
- `build.mjs`: page templates, service content and SEO metadata.
- `dist/assets/site.css`: visual design, responsive layouts and animation.
- `dist/assets/site.js`: gallery, filter, navigation and enquiry interactions.

## Product imagery

The four views for each product are stored in one square, four-quadrant WebP file under `dist/assets/products`. The gallery displays each view individually with CSS. This avoids four separate downloads while retaining four different views, not four copies of the same photograph. Concept views can contain variations and must not be treated as manufacturing drawings.

Original generated PNGs and prompts are kept outside this checkout in `../outputs/arviga_site_assets`. `prepare-assets.py` performs format compression only, preserving the whole image. It is an optional authoring utility requiring Pillow; deployment itself needs no Python.

Replace concept photography with approved photographs of the actual product before selling a specific SKU. The current entries are product types, not verified purchasable models. The interface clearly labels imagery and prices as illustrative.

## Enquiries

Until an email or WhatsApp number is configured, the form downloads a text brief and explicitly says it has not been sent. It does not pretend to submit an enquiry. Once `email` or `whatsapp` is configured, the form opens the visitor's corresponding application for review and sending. No website database is involved.

For a reliable direct-submit form, connect a form service or a small serverless endpoint with validation, spam protection, rate limiting and email delivery. Provider pricing must be checked before enabling it. Never put email-service secrets in browser JavaScript.

There is no checkout, payment gateway, order inventory or user account system in this version. The Amazon-style product presentation supports quotation enquiries. Those commerce capabilities need separate confirmed requirements and operating policies.

## Low-cost hosting

Upload `dist` to a static host. Cloudflare Pages currently provides free static requests within its platform limits. Domain registration, professional email and optional enquiry services are separate costs. No VPS, WordPress hosting, managed database or always-on Node server is required. Current references:

- https://developers.cloudflare.com/pages/functions/pricing/
- https://developers.cloudflare.com/pages/platform/limits/

The Sites copy is private for review. Its access and billing are governed by the user's Sites account, not by Cloudflare's direct-to-customer free plan.

## Before a public launch

1. Confirm business name, public domain, address/service areas, phone, WhatsApp and enquiry email. Replace the review origin in `data/business.json` with the final domain.
2. Confirm product models, dimensions, materials, finishes, prices, GST/tax treatment, quantities, lead times and delivery/installation coverage.
3. Replace example prices and update their labels only after approval. Add real Offer structured data only when the visible price, currency and availability are accurate.
4. Supply warranty, cancellation, returns, delivery and privacy terms appropriate to the actual business. Do not publish invented certifications, client logos, reviews or performance claims.
5. Review AI concept imagery and service descriptions against actual capabilities. Add genuine factory/product photographs and case studies when available.
6. Connect and test the actual enquiry channel, including receipt and spam handling.
7. Set `publicLaunch` to true only for a ready, publicly accessible site; rebuild and verify the production robots.txt, canonical URLs and sitemap.xml. Private review remains noindex and disallowed in robots.txt.
8. Verify the domain in Google Search Console, submit the sitemap, inspect representative URLs and monitor indexing. Configure a Google Business Profile when eligible and maintain consistent business details.
9. Measure mobile Core Web Vitals on the final host. This version includes compressed WebP catalogue imagery, lazy loading, explicit image dimensions and minimal JavaScript, but no claimed Lighthouse score or ranking guarantee.

Google guidance: https://developers.google.com/search/docs/essentials and https://developers.google.com/search/docs/fundamentals/seo-starter-guide

## Validation

`node check.mjs --complete` checks all generated routes, local links and images, unique titles/descriptions, JSON-LD, canonical tags, 74 product pages, nine service pages and four gallery controls per product. It rejects missing catalogue imagery and structured price offers on concept products.

Browser checks cover desktop/mobile layout, navigation, product search, galleries and image enlargement, finish/quantity enquiry handoff, and local enquiry download. These are design and functionality checks, not evidence of real product specifications or a guarantee of Google ranking.

Where supported, optional WebMCP tools expose the same visible catalogue filtering and product enquiry configuration. Both tools were checked with valid and invalid inputs; neither sends messages or creates orders. Full image-generation prompts are recorded in `data/image-prompts.json`.
